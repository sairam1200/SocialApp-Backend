## 1. Executive Summary

This document defines the schema changes required to extend `contentStreams` for unified search. New columns are added to support full-text search, ranking signals, and pre-computed search text. All changes are additive — no existing columns are modified or removed.

The migration follows the principle of zero-downtime deployments: new columns are nullable, old code continues to work, and the feature flag controls when new columns are used.

## 3. Extended Schema

```sql
ALTER TABLE "contentStreams"
  ADD COLUMN "searchText" TEXT,
  ADD COLUMN "searchVector" TSVECTOR,
  ADD COLUMN "publishedAt" TIMESTAMP,
  ADD COLUMN "engagementScore" FLOAT,
  ADD COLUMN "creatorId" VARCHAR;
```

### 3.1 New Columns

| Column | Type | Nullable | Default | Purpose |
|---|---|---|---|---|
| `searchText` | text | yes | null | Pre-computed search text |
| `searchVector` | tsvector | yes | null | PostgreSQL full-text search vector |
| `publishedAt` | timestamp | yes | null | Content publication date |
| `engagementScore` | float | yes | null | Pre-computed engagement metric |
| `creatorId` | varchar | yes | null | Creator identifier |

### 3.2 Column Definitions

#### searchText

Pre-computed search text generated by SearchDocumentBuilder:

```sql
-- Example value
'searchText = "how to build a rest api with node.js in this tutorial we build a rest api using express.js and typescript nodejs typescript api tech academy"'
```

**Generation:** Application code (NOT `GENERATED ALWAYS AS`)

**Rationale:** Allows future AI tags, OCR, transcripts, synonyms, multilingual tokens.

#### searchVector

PostgreSQL full-text search vector:

```sql
-- Example value
searchVector = to_tsvector('english', 'how to build a rest api with node.js')
```

**Generation:** Application code or database trigger

**Index:** GIN index for fast full-text search

#### publishedAt

Content publication date extracted from platform-specific fields:

```sql
-- YouTube: snippet.publishedAt
-- Facebook: created_time
-- Instagram: timestamp
-- Pinterest: created_at
```

**Index:** B-tree index for date range queries

#### engagementScore

Pre-computed engagement metric (0-1):

```sql
-- Example calculation
engagementScore = (viewScore * 0.4) + (likeScore * 0.3) + (commentScore * 0.2) + (subscriberScore * 0.1)
```

**Index:** B-tree index for sorting

#### creatorId

Platform-specific creator identifier:

```sql
-- YouTube: snippet.channelId
-- Facebook: from.id
-- Instagram: user.username
-- Pinterest: board.owner
```

**Index:** B-tree index for creator-based queries

## 4. Indexes

### 4.1 Full-Text Search Index

```sql
CREATE INDEX "IDX_contentStreams_searchVector" 
  ON "contentStreams" USING GIN("searchVector");
```

**Purpose:** Fast full-text search using `tsvector` and `to_tsquery`

**Size:** ~20-30% of table size

**Performance:** O(log n) for text search queries

### 4.2 Trigram Index

```sql
CREATE INDEX "IDX_contentStreams_searchText_trgm" 
  ON "contentStreams" USING GIN("searchText" gin_trgm_ops);
```

**Purpose:** Fuzzy matching and similarity search using `pg_trgm`

**Extension required:** `CREATE EXTENSION IF NOT EXISTS pg_trgm;`

**Size:** ~50-100% of table size

### 4.3 Publication Date Index

```sql
CREATE INDEX "IDX_contentStreams_publishedAt" 
  ON "contentStreams"("publishedAt");
```

**Purpose:** Date range queries and freshness-based sorting

**Size:** ~10% of table size

### 4.4 Engagement Score Index

```sql
CREATE INDEX "IDX_contentStreams_engagementScore" 
  ON "contentStreams"("engagementScore");
```

**Purpose:** Engagement-based sorting

**Size:** ~5% of table size

### 4.5 Creator ID Index

```sql
CREATE INDEX "IDX_contentStreams_creatorId" 
  ON "contentStreams"("creatorId");
```

**Purpose:** Creator-based queries

**Size:** ~5% of table size

### 4.6 Partial Index for Search

```sql
CREATE INDEX "IDX_contentStreams_search_partial" 
  ON "contentStreams"("platform", "type") 
  WHERE "searchVector" IS NOT NULL;
```

**Purpose:** Efficient filtering by platform and type for indexed documents

**Size:** ~10% of full index size

### 5.2 Backfill Script

After migration, backfill existing data:

```sql
-- Backfill searchText from title + metaData
UPDATE "contentStreams"
SET "searchText" = LOWER(
  COALESCE("title", '') || ' ' ||
  COALESCE("metaData"->>'description', '') || ' ' ||
  COALESCE("metaData"->>'channelTitle', '') || ' ' ||
  COALESCE("metaData"->>'author', '')
)
WHERE "searchText" IS NULL;

-- Backfill searchVector from searchText
UPDATE "contentStreams"
SET "searchVector" = to_tsvector('english', "searchText")
WHERE "searchVector" IS NULL AND "searchText" IS NOT NULL;

-- Backfill publishedAt from metaData
UPDATE "contentStreams"
SET "publishedAt" = ("metaData"->>'publishedAt')::TIMESTAMP
WHERE "publishedAt" IS NULL AND "metaData"->>'publishedAt' IS NOT NULL;

-- Backfill engagementScore
UPDATE "contentStreams"
SET "engagementScore" = LEAST(
  COALESCE(("metaData"->>'viewCount')::FLOAT / 10000000, 0) * 0.4 +
  COALESCE(("metaData"->>'likeCount')::FLOAT / 1000000, 0) * 0.3 +
  COALESCE(("metaData"->>'commentCount')::FLOAT / 100000, 0) * 0.2 +
  COALESCE(("metaData"->>'subscriberCount')::FLOAT / 10000000, 0) * 0.1,
  1.0
)
WHERE "engagementScore" IS NULL;
```

## 6. Performance Impact

### 6.1 Storage

| Component | Size | Notes |
|---|---|---|
| `searchText` | ~50 bytes/row | Average text length |
| `searchVector` | ~30 bytes/row | Compressed tsvector |
| `publishedAt` | 8 bytes/row | Fixed size |
| `engagementScore` | 8 bytes/row | Fixed size |
| `creatorId` | ~20 bytes/row | Average ID length |
| **Total** | **~116 bytes/row** | ~10% overhead |

### 6.2 Index Size

| Index | Size | Notes |
|---|---|---|
| GIN (searchVector) | ~20-30% of table | Full-text search |
| GIN (searchText trgm) | ~50-100% of table | Fuzzy matching |
| B-tree (publishedAt) | ~10% of table | Date queries |
| B-tree (engagementScore) | ~5% of table | Sorting |
| B-tree (creatorId) | ~5% of table | Creator queries |
| **Total** | **~90-150% of table** | Significant overhead |

### 6.3 Query Performance

| Query Type | Before | After | Improvement |
|---|---|---|---|
| Full-text search | 20-100ms | < 10ms | 2-10x |
| Fuzzy matching | 50-200ms | < 20ms | 2-10x |
| Date range | 10-50ms | < 5ms | 2-10x |
| Engagement sort | 20-100ms | < 10ms | 2-10x |
